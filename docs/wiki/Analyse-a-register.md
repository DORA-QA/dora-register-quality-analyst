# Analysing a register

## Which file should I drop?

The file you submit (or are about to submit) to the authority:

- the xBRL-CSV **ZIP package** produced by your reporting tool (EBA format);
- or the OneGate **XML envelope** that contains it (ACPR submission).

One register at a time, 100 MB at most.

> A real register must only be analysed on a computer where the tool is **authorised by your IT department** (see [Self-service and IT](Self-service-and-IT)).

## Steps

1. Start DORA QA and accept the disclaimer.
2. Click **Choose a file** (or drag the file onto the "Deposit a register of information" area).
3. Wait a few seconds: the analysis runs on your computer.
4. The report is displayed: see [Reading the report](Read-the-report).

## Correct and start again

1. Note the findings to correct (or export them).
2. Correct the register **in your usual reporting tool**, then generate the ZIP or the XML again. DORA QA never changes your file.
3. Drop the new file: a new analysis starts.

## Changing the language

**EN | FR** selector at the top right. The findings are then displayed in the chosen language.

## Discovering the tool without a real register

The `exemples` folder of the ZIP contains **entirely fictitious** registers, including one deliberately full of errors: ideal for a demonstration or a training session.
